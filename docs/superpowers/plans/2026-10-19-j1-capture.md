# J1 — PR 1 : service de séance et rangement

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** le service natif tient la ceinture et écrit une séance par fichier ; l'app range chaque
journal en base (séance + trames), y compris celui d'une séance tuée, et l'export emporte les trames.

**Architecture :** `SurvieService` devient `SeanceService`, seul détenteur de la ceinture, avec deux
modes — *écoute* (relaie la FC, n'écrit rien) et *enregistrement* (écrit `seance-<uuid>.log`, compte le
temps en zone). La séance active est écrite dans des `SharedPreferences` avant la première trame ; un
redémarrage par Android rejoue le journal. Le greffon `Seance` remplace `Survie`. Côté TS, un lecteur
pur du journal (zod) produit séance + trames ; le rangement écrit les deux dans une transaction Dexie,
puis seulement demande l'effacement du fichier.

**Tech Stack :** Kotlin (JUnit 4 sur la JVM), Capacitor 8, TypeScript, zod 4, Dexie 4, Vitest, Playwright.

**Spec :** `docs/superpowers/specs/2026-10-19-j1-capture-live-design.md`

## Global Constraints

- La donnée n'est jamais perdue : un journal n'est effacé qu'après la transaction Dexie réussie ; un
  journal illisible n'est **jamais** effacé.
- Aucune valeur dérivée stockée, sauf `avgHrBpm` (sujet 11, 2026-09-20) : moyenne des `bpm` des trames.
- Trame rangée = `{ t_ms, bpm, rr: number[] }`, `t_ms` depuis le départ. Contact peau et événements de
  liaison restent dans le journal.
- Le service seul tient la ceinture pendant une séance ; aucun code ne lit le fichier pendant qu'il est
  la séance active.
- Seuil de silence : **5 000 ms** (le même que `CapteurPlugin.SILENCE_MS`).
- Textes exacts : « Séance de N min retrouvée » · « Une séance n'a pas pu être rangée ».
- Aucun code de test dans l'app : le banc injecte `window.Capacitor` (modèle `e2e/capteur.ts`).
- Rien d'identifiant dans le dépôt (pas de chemin absolu, pas de donnée réelle dans les fixtures).
- Commits Conventional, ≤ 72 caractères, `npm run lint && npm run test` avant chacun.

   `avgHrBpm`. Test dans la tâche 4.
2. **Journal sans aucune trame** (séance démarrée, ceinture jamais revenue) : rangé avec sa durée,

   Test tâche 6 (banc).

  ```ts
  // `Trame` vit dans src/db/schema.ts (créée ici) : { t_ms: number; bpm: number; rr: number[] }
  export interface Lu { session: Session; trames: Trame[] }
  export function lireJournal(texte: string, maintenant?: Date): Lu | null   // null = illisible
  export function minutesManquantes(trames: Trame[], durationS: number): number
  ```

- Règles :
  - Première ligne `D` invalide → `null`. Toute ligne invalide **autre que la dernière** → `null`.

  - `id` = uuid de `D` ; `startedAt` = `debutMs` en ISO ; `source: 'live'` ; `createdAt`/`updatedAt` = `maintenant`.
  - `durationS = max(1, round((fin − debutMs) / 1000))`, `fin` = ms de `S`, sinon de la dernière ligne lue.
  - `avgHrBpm` = moyenne arrondie des `bpm > 0` ; absent s'il n'y en a pas.
  - `t_ms = ms − debutMs`. Lignes `C` et `R` lues (valides) mais non rangées.
  - `minutesManquantes` : somme des écarts > 5 000 ms entre 0, chaque `t_ms` et `durationS*1000`, en minutes entières par défaut (`Math.floor`).
  - Schéma zod par type de ligne ; `bpm` entier 0–255, `rr` entiers positifs.
